# Per-target publication diagnostics

These are isolated counter experiments on a copied materializer source. They do not edit production. Instrumented durations and allocations are retained as raw harness fields but are never used to rank implementations. A frozen run plan is created before each suite, and all query records, process commands, route observations and owner records are preserved without replacement runs.

The initial diagnostic uses original dense 64-cell pages, DENSE coordinate transport, ordinary reuse, the preserved common two-fixture harness, a fixed 1 GiB G1 heap, a 1 GiB global ledger, a 512 MiB per-query ledger, normal AUTO selection, three warmups and one observed query per fresh JVM. Full consumption and fixture data are exactly those of the completed compact-page study. Increasing the query allowance is explicit: this first diagnostic measures which targets supply hits without reproducing the original shared-tail admission cap. Separate 256 MiB diagnostics can establish admission relief; their timing is still excluded.

The fanout discovery rule is fixed before execution: a candidate canonical bank must have positive page admissions and completed publications, zero successful factor hits, and zero factor weak-reference or witness misses in every one of the four queries. Requested-target hit and publication counters are summed over all aliases of that canonical bank; page counters are already canonical. Zero-page targets are excluded, even if they have zero hits, because they would introduce a different failed-coordinate-capture ablation. Shared-tail's proposed mask is fixed as `l0,l1`; its diagnostic checks must support the same conditions before timing. This is an observed-fixture exclusion rule, not proof that future executions cannot benefit from these entries.

Every counter except page admission/claims/releases is attributed to the requested projection target. Page admission/claims/releases and page records are attributed to the canonical target stored in the production page key. Each target record includes the canonical target, cache bank and definite source slot. Aliases must be aggregated explicitly before interpreting a target mask. Publication skip counts occur at the experimental guard before coordinate capture, and the mask suppresses only publication; factor lookup, transport, value witnesses and ordinary reuse remain active.

The helper retains no Values, sources, weak references or coordinate owners. It adds no WeakReference.get calls. Occupancy at close counts non-null weak-reference cells without dereferencing them, so occupied cells do not imply live referents. It captures primitive page keys and charge amounts before the existing close, then writes JSON after close. Its field/counter/allocation/output overhead still makes its performance unsuitable for comparison.

Internal equations check the complete partition of ordinary lookup outcomes, factor lookup outcomes, publication exits and admission outcomes. Page grants must equal observed explicit releases. The independent harness checks rows, checksum, normal AUTO/native IR selection, compiled observed-query tier, positive active-adjacency lookup hits, zero query ledger endpoints and zero hosted generic roots. Shared-tail also uses its exact independent bag oracle. Fanout retains the original count/checksum oracle and consumption.

Use `build_overlay_source.py --source <frozen source> --output <fresh diagnostic folder>` to generate the isolated Java source and patch. The generator verifies unchanged plan and page/memo source regions relative to its input and preserves the preimage. After the coordinator grants the Java slot, `run_diagnostic.py compile --generated <folder> --base-runtime <descriptor> --slot-granted` compiles and selects only the materializer outer class and diagnostic helper ahead of the base runtime. The plan and nested page/memo classes stay in the selected base runtime. `run_diagnostic.py prepare --name <fresh suite> --runtime <runtime.json> --query-limit <bytes> --mask <canonical names> --fixtures <fixtures>` freezes a prospective plan. `run_diagnostic.py run --name <suite> --slot-granted` runs its serial fresh JVMs and checks raw counter equations and result/routes. These commands create fresh directories and reject overwrites.
