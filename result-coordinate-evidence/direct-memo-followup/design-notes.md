# Direct memo: first experimental decisions

The requested adaptive policy is retained: an initial capacity of 4,096 slots, one low-hit cutoff at 8,192 probes, growth from 16,384 onward at 8,192-probe boundaries, cumulative hit and collision thresholds of 25% and 12.5%, and a cap of 65,536 slots. Collisions replace entries directly, without probing or LRU. The full position mask participates in the key. Within-row duplicate detection precedes lookup.

The current iteration owner is `NativeResultMaterializer`. It already validates source, result-view, and exposure identities, repairs provisional hits, and closes with the iteration. The new table uses that owner instead of changing `AggContext`, whose cache serves internal aggregate evaluation. The direct arm bypasses both ordinary per-column reuse and coordinate factor reuse. Publication on a direct miss is immediate; deferring it until row completion would alter collision behavior.

A fifth parallel array captures each native value's `InternalIdentity`. This is necessary because `setInternalID` may change the dictionary association without incrementing the semantic version. Hits compare the saved semantic version, ID, revision number, and revision owner, allowing legitimate replacement of the revision object during initialization. The separately generated four-array prototype is a correctness counterexample only; it fails all three required identity-invalidation tests.

The five array estimates use 16-byte headers and 8-byte references: `80 + 36 * capacity` bytes. At 4,096 slots this is 147,536 bytes; at 65,536 it is 2,359,376 bytes. A growth reservation includes both generations until replacement is complete, reaching 3,539,104 bytes for the final doubling. These are array estimates, not measured heap. Strong `Value` references and captured old identity/revision capabilities remain uncharged; later initialization can grow their retained graphs.

Individual reads and projected-value collection use the same memo. They do not receive the explicit Sail exposure token. A native dictionary value that is not externally owned therefore still passes through ordinary `source.lazyValue` when returned by those paths, preserving its exposure-dependent ownership handoff. A validated table hit is consequently a candidate for reuse, not a guarantee of an avoided source call. The raw source-call counters remain authoritative. Accepted Sail capture uses its supplied exposure token and can reuse the valid object directly.

Primary timings retain natural GC, the same ownership implementation, the original dense coordinate pages, normal AUTO selection, and the exact preserved inputs. The controls may experience natural weak misses. Raw source-call counts are outcomes, not equality requirements. The first-window cutoff is kept unchanged while measuring the described policy: a delayed-repetition contract demonstrates that subsequent reuse cannot revive the disabled table.

For comparison, PostgreSQL's `cost_memoize_rescan` accounts for lookup, entry creation, tuple storage, and eviction as well as underlying work saved. This supports measuring total query cost rather than selecting an implementation from hit rate or allocation alone. Its executor can bypass caching under memory pressure and reconsider caching on a subsequent rescan. These are design comparisons; no code or dependency was copied. PostgreSQL Memoize stores tuples using a hash table and LRU eviction, which differs from this direct-mapped table of strong value references.
