# Repeated promotion refusal and later recovery

This candidate-only synthetic probe counts repeated attempts under deterministic memory pressure. It is separate from the two full shared-tail queries and from every performance comparison. It makes no AUTO, native query-root or adjacency claim: it calls existing package-local materializer interfaces using a minimal synthetic source.

Use the exact compact diagnostic runtime plus one new probe class prefix. The source deliberately retains immutable values A and B so weak-reference collection does not randomize the probe. A has ID 42 and offset 0; B has ID 43 and offset 1 in the same factor page. First capture A. A 20,000-byte standalone manager should charge 2,496 bytes for the ordinary memo, directory, compact shell and coordinate memo. Reserve all remaining memory except 128 bytes in a competing claim with observable spill/shed callbacks.

Perform 1,024 B/A alternations. Each B attempts an unaffordable 15,872-byte promotion and resolves through the source; each A must still be a factor-cache hit. After every pair require unchanged cache charge and unchanged constrained ledger. Release the competing claim, then capture B/A/B. B must promote and both later captures must reuse the two retained members.

The prospective exact counts are 2,052 captured rows, numeric ID checksum 87,210, one A resolver call, 1,025 B resolver calls, 1,025 promotion attempts, 1,024 refusals, one success and 1,026 factor hits. No spill/shed callback may run. The final page must be dense with occupied-offset mask 3, two stored weak-reference slots, one 512-byte shell and one 15,872-byte payload. Total materializer charge after promotion is 18,368 bytes; close must release all claims before ledger close. The competing claim should cause the 20,000-byte manager's peak to be 19,872 bytes. Fields named `processLedger*` in the raw probe JSON refer to this standalone testing manager, not the process-wide singleton authority used by the full query harness.

These counts validate persistent retries and recovery; they do not estimate their CPU cost. A failed reservation acquires the manager monitor on each attempt. No elapsed-time metric is collected here. Unexpected counts, runtime drift or process failure preserve all evidence and stop the probe; no replacement run is allowed under this protocol. Source/runtime/JVM hashes and arguments are pinned before compilation/execution, injected Java option environment variables are rejected, and the coordinator must grant a separate compiler/JVM slot.
