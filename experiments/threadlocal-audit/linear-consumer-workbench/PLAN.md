## Problem and semantic boundary

The prior Node harness retains a partial NDJSON line in carry across chunks and searches from offset zero after every append. Source-line profiles show substantial repeated delimiter-search work. Actual Workbench queryStream.ts already uses a fragment splitter scanning only each new chunk; the frozen browser bundle matches that implementation. Therefore this is a benchmark endpoint repair, not a browser bug or proof of a server regression.

Use a pure fragment accumulator: search only the newly decoded chunk, preserve the unconsumed tail as fragments, and join exactly once when its newline arrives. Emit each line lazily/immediately so the first rows-batch timestamp remains after JSON.parse of the first rows record, not after eagerly scanning/parsing the entire incoming chunk. Preserve fatal incremental UTF8 decoding, empty lines, CRLF, multiple records per chunk, partial tails across empty decoder output, error-record propagation and old EOF trim-empty/terminal rules. Do not begin accepting unterminated JSON. Leave query, metrics, protocol request, source code, classpaths, fixtures and all engine flags unchanged.
