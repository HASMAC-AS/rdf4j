# Separate actual-path profiles

Some portions generated by Codex. No new clean timing round.

Two fresh server JVMs, base then depth, exact same production layers/flags/query/full window as the completed matched experiment. Twenty query warmups, then a recording spanning 30 full requests. Warmup is excluded by a programmatic JFR start endpoint; a stop endpoint dumps after the final request. This is a separate diagnostic harness class/directory, not a modification of the frozen clean harness or its existing outputs. CPU lock spans each complete lifecycle, after correctness worker handoff.

The recording includes actual server and colocated Workbench Java threads, binary writer/parser, read/replay/initializer scopes, servlet and background executor work. It also includes idle periods during Node process/session setup and metrics calls between requests. Report Java execution samples separately from native idle/socket samples. Node JSON decode/client CPU is NOT in JVM JFR. Browser remains blocked; no rendering/profile claim. None of these durations are new clean timing data.

Analyze all relevant JVM threads, not only main. Retain top threads, full sampled stacks and ThreadLocal leaf/nearest caller counts. Classify actual query/kernel/materialization, read/lifetime/replay, binary writer/parser, Workbench NDJSON, transport mapping, and container/other work. Categories may overlap; sample percentages are not wall-time costs or exact invocation counts. Compare helper-aggregated scopes, not absence of a renamed helper. Use the result to rank hypotheses for the actual route, not to assert an engine delta was causally erased by a specific component without evidence.
