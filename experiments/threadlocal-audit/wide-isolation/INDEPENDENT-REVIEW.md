## Why width is more than five times the same work

The WHERE body and100k Cartesian rows are fixed, but projected extra attributes change materialization, memo keys/requests, DISTINCT key width and binary/NDJSON payload. Each arm contributes four always-bound and four80%-bound language attributes:24 extra slots average21.6 bound values, hence27.6 bound terms per wide row versus6. Wide text includes Unicode and language metadata, whereas original nodes are shorter IRIs. This is not a pure slot-count factor with identical lexical encoding cost. Null slots still emit JSON null and binary markers.

The unchanged compact writer creates one packed row and Object[] per bound term; language arrays carry four fields versus two for an IRI. Typed serialization removes generic dispatch, not these arrays, generator/context lifecycle, UTF8 encoding or structural validation.256KiB row-record cap can flush well before the normal1024-row batch on wide data. Report rows-record counts/bytes, and preferably rows-record segmentation separately from progress/metadata record counts. Equal term bags alone do not prove equal output order/segmentation.

First-row metric remains first parsed rows batch, not first tuple. Report equal output bytes/row records or explain metadata/order differences.
