# Matched query and binary serialization profiles

This is an in-process, real LMDB repository executing the existing synthetic 2.136-million-triple OPTIONAL fixture and returning 8 million 30-column rows. It is not the private user query or an HTTP/Workbench end-to-end test.

Versions and classpaths are frozen from `main-comparison`: upstream main be0c4c724f and combined experimental production b8104ecf51. A single identical harness is compiled against both. Experimental memo, readiness, primitive DISTINCT, grouping, bulk spill and miss-slot flags remain enabled. Heap 5 GiB; configured global/per-query budgets 2.5 GiB/640 MiB. Main's DISTINCT accounting differs and must not be construed as equal effective budget enforcement.

Four initial profiles: combined with binary writer; main with binary writer; main materialization consumer only; combined consumer only. Runs serialize under the common benchmark lock. JVM-wide JFR recordings are started after store warming and stopped immediately after result consumption. CPU execution/native samples and weighted allocation samples are collected. Recorded query includes query preparation, iteration, all projected string values and checksum. Writer variant additionally uses actual BinaryQueryResultWriter, writing into a byte-counting OutputStream, not disk/network. Byte checksum is disabled during performance measurement to avoid adding a byte-at-a-time hashing bottleneck. This sink does not reproduce network backpressure.

For fair ablation, both writer and no-writer variants retain the same lexical checksum; therefore writer timing is incremental serialization cost atop a fully consuming harness, not a claim of exact production endpoint time. Allocation totals cover query thread; JFR sampled weights are statistical. Inclusive stack percentages overlap and are not wall-time percentages. First runs are cold-query, compilation included; source checks, route/compiled counts, rows/checksum, spill cleanup and experimental witnesses are retained.
